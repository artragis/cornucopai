# Implementation Plan: Style de code Java — lint (Checkstyle) et formatage automatique (Google Java Style)

**Branch**: `008-java-code-style` | **Date**: 2026-11-12 | **Spec**: [specs/008-java-code-style/spec.md](spec.md)

**Input**: Feature specification from `/specs/008-java-code-style/spec.md`

## Summary

Add repo-level Java style enforcement to the Maven backend (`backend/`): a
**Checkstyle** lint that fails `./mvnw verify` on any Google Java Style violation,
and a **Spotless** formatter (`spotless:apply` to format, `spotless:check` bound to
`verify`) using **google-java-format 2.0.0** (Spotless 3.11.0 default). The
Checkstyle rules are the official `google_checks.xml` from Checkstyle 14.4.0,
vendored under `backend/config/checkstyle/` with a suppressions file that relaxes
only the `MissingJavadoc*` checks (recorded trade-off, R-066). Because the existing
CI job already runs `./mvnw verify` (`.github/workflows/ci.yml`), both the lint and
the format check become blocking in CI with **no workflow change**. An initial
`spotless:apply` pass reformats all ~125 existing Java files before the gates go
live. Decisions: `research.md` (R-063…R-067); config entities: `data-model.md`;
developer command contract: `contracts/build-commands.md`; validation:
`quickstart.md`.

## Technical Context

**Language/Version**: Java 25 (backend, `maven.compiler.release=25`); Maven wrapper 3.9.x (`backend/mvnw`)

**Primary Dependencies**: Build-tooling only, added to `backend/pom.xml` `<build><plugins>`:
- `org.apache.maven.plugins:maven-checkstyle-plugin` **3.6.0** with plugin dependency `com.puppycrawl.tools:checkstyle` **14.4.0** (latest release; confirmed buildable on JDK 21–25 and able to parse all Java 25 language features — verified against checkstyle.org and Maven Central metadata 2026-11-12)
- `com.diffplug.spotless:spotless-maven-plugin` **3.11.0** (released 2026-11-02; its default `googleJavaFormat` is **google-java-format 2.0.0**, which runs on JDK 21+ — compatible with our JDK 25; GJF 2.0.0 requires a JDK ≥ the source level being formatted, satisfied since we run JDK 25)

No runtime/production dependency changes; the Quarkus application and its
debug mode (`./mvnw quarkus:dev`, JDWP 5005) are untouched.

**Storage**: N/A (no data). Configuration files live in the repo under `backend/config/checkstyle/`.

**Testing**: Existing backend test suite (JUnit 5 + AssertJ + REST Assured, 125 Java files) must keep passing after the initial format pass. New validation is behavioral (build fails/passes), exercised via the commands in `contracts/build-commands.md` and `quickstart.md` — no new unit tests required for build tooling, but the full `./mvnw verify` MUST pass green at the end.

**Target Platform**: Linux CI (GitHub Actions, `ubuntu-latest`, Temurin 25) and any developer machine with JDK 25.

**Project Type**: Web application (backend + frontend); this feature touches **backend only**.

**Performance Goals**: `checkstyle:check` adds < 30 s to `./mvnw verify` (SC-002); `spotless:apply` over the whole backend completes < 60 s (SC-003). Both are one-shot build steps, not runtime paths.

**Constraints**: Code generated by Quarkus under `backend/target/` MUST be excluded from both lint and format (default Spotless/Checkstyle source sets already exclude `target/`; asserted explicitly in config). `./mvnw quarkus:dev` debug launchability (JDWP 5005) MUST be preserved (constitution). All new dependencies pinned and license-reviewed (both plugins are Apache-2.0; google-java-format is Apache-2.0; checkstyle is LGPL-2.1 — build-time only, not shipped, recorded per constitution).

**Scale/Scope**: ~125 Java files under `backend/src/main/java` and `backend/src/test/java` (counted 2026-11-12); single Maven module.

**Structure Decision**: Backend-only change. The style config is vendored under
`backend/config/checkstyle/` (standard Checkstyle layout) rather than referenced
from the Checkstyle JAR, so the exact ruleset is versioned in the repo (FR-008) and
can carry project suppressions. No new top-level source directory is introduced,
complying with the constitution's repository-layout rule.
